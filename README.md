# منصة لجنة المسؤولية المجتمعية · سنكري القابضة

> **جلسة جديدة؟** هذا المستودع هو منصة اللجنة: خادم Node بلا إطار عمل (`server.js`) وواجهة صفحة واحدة (`index.html` + `js/app.js` + `css/style.css`). البيانات كلها في مستند JSON واحد. **المنصة الآن على خادم خاص وتحفظ في ملف على قرصه** (`data/store.json`)، ولم تعد تستعمل Neon ولا Render. اقرأ هذا الملف كاملاً قبل أي تعديل، وخاصة القسم 2 (ما تغيّر عن النسخة الأولى) والقسم 7 (قواعد العمل).
>
> **قواعد ثابتة:**
> - شغّل `npm run check` قبل كل تسليم.
> - ارفع رقم `?v=N` في `index.html` عند أي تغيير في `js/app.js` أو `css/style.css`.
> - كل تسليم حزمة جديدة برقم تالٍ، لا كتابة فوق حزمة سابقة.
> - حدّث هذا الملف و«سجل الإصدارات» (القسم 9) مع كل تغيير.

## 2. ما الذي تغيّر عن النسخة الأولى (1.0.0 ← 1.1.0)

النسخة الأولى كانت تعمل على Render المجاني وتُعلَّق عند نفاد الحد الشهري. هذه التعديلات تجعل الاستهلاك قليلاً على أي استضافة، دون تغيير في الواجهة أو في سلوك المستخدم.

### 2-أ. ملفات حُذفت
| الملف | السبب |
|---|---|
| `app.js` و`style.css` في الجذر | نسخ قديمة مكررة غير مستعملة. المصدر الوحيد الآن `js/app.js` و`css/style.css`. |
| `Dockerfile` | استُبدل بتشغيل Node مباشرة (`node server.js`)، فالبناء أخفّ وأسرع. |

### 2-ب. `server.js`
| التغيير | أين في الكود | لماذا |
|---|---|---|
| **الملفات الثابتة في الذاكرة.** تُقرأ كلها عند التشغيل وتُضغط gzip مرة واحدة، ولكل ملف `ETag` (بصمة sha1). | `loadStatic()` · `serveStatic()` · الخريطة `files` | كان كل فتح يقرأ الملف من القرص ويرسله كاملاً بلا ضغط (≈330KB). الآن يُرسل مضغوطاً (≈100KB أول مرة) ثم لا شيء تقريباً. |
| **قواعد التخزين في المتصفح.** ملف عليه `?v=N` ← `max-age=31536000, immutable`. ‏`index.html` ← `no-cache` مع ETag (رد 304 بلا محتوى). ‏غيرها ← يوم واحد. | `serveStatic()` | لهذا يجب رفع `?v=N` عند كل تغيير في js/css، وإلا بقي المستخدمون على النسخة القديمة سنة. |
| **مسار غير موجود.** ملف ناقص داخل `/css/` أو `/js/` أو `/assets/` ← 404. أي مسار آخر ← `index.html`. | `serveStatic()` | الوصول مقصور على الخريطة `files`، فلا يمكن قراءة `server.js` أو `data/` من المتصفح. |
| **ضغط ردود JSON** الأكبر من 1KB. | `send()` · `gzipOk()` | المستند الكامل (مع صور المشاريع) هو أثقل ما يخرج من الخادم: ‏44KB ← 10KB في التجربة. |
| **النسخة اليومية في Postgres** تُكتب مرة كل ساعة على الأكثر بدل كل حفظ، وتُحذف بعد 30 يوماً. | `makeStore()` (فرع postgres) · `BACKUP_EVERY_MS` · `BACKUP_KEEP_DAYS` | كان كل حفظ، حتى رسالة واحدة، يرسل المستند كاملاً مرتين. **لا يخصّ وضع الملف الحالي** (انظر 4-ب). |
| **اتصال Postgres:** حدّ أقصى 3 اتصالات، تُغلق بعد 10 ثوانٍ من الخمول، ومعالج `pool.on('error')`. | `makeStore()` | Neon يقطع الاتصالات الخاملة حين ينام، وبلا المعالج كان الخادم يسقط. |
| **إغلاق منظّم عند `SIGTERM`.** تُنهى الطلبات والكتابات الجارية ثم يُغلق الخادم (حدّ أقصى 8 ثوانٍ). | آخر الملف | يحدث عند كل إعادة تشغيل أو نشر. |
| **تحذير في السجل** إن لم يُضبط `SESSION_SECRET`. | آخر الملف | بدونه يتولّد مفتاح جديد عند كل تشغيل، فيخرج الجميع من حساباتهم. |

لم يتغيّر: الحسابات وكلمات المرور (scrypt)، والجلسات (رمز موقّع HMAC صالح 30 يوماً)، والواجهة البرمجية، وصيغة البيانات، وقواعد الصلاحيات.

### 2-ج. `js/app.js`
تغيير واحد في `boot()`: **التحديث التلقائي (`pull`) يعمل فقط والصفحة ظاهرة وفيها نشاط** خلال آخر 10 دقائق (`IDLE_MS`). النشاط هو: نقر أو لمس أو حركة فأرة أو كتابة أو تمرير.
- **قبل:** كل صفحة مفتوحة، حتى المنسية في تبويب خلفي، تطلب التحديث كل 15 ثانية إلى الأبد، فلا يرتاح الخادم.
- **الآن:** يتوقف التحديث في الصفحة المخفية أو الخاملة، ويعود فوراً مع سحب فوري عند أول لمسة أو عند العودة إلى التبويب.
- الحفظ (`push`) لم يتغيّر: يُرسَل بعد 400ms من أي تعديل.

### 2-د. ملفات أخرى
| الملف | التغيير |
|---|---|
| `index.html` | `?v=11` ← `?v=12` |
| `package.json` | الإصدار 1.1.0 · `engines: node 22.x` · الأمران `npm run check` و`npm run copy-db` |
| `render.yaml` | Node مباشرة بدل Docker، والمنطقة frankfurt. **لم يعد مستعملاً**، وبقي بديلاً جاهزاً (القسم 8). |
| `.gitignore` | جديد: `node_modules/` · `data/` · `.env` |
| `tools/smoke.js` | جديد: فحص آلي من 32 بنداً (القسم 7) |
| `tools/copy-db.js` | جديد: نسخ البيانات بين قاعدتي Postgres (لم يعد لازماً بعد ترك Neon) |

### 2-هـ. نقل البيانات من Neon (تم، مرة واحدة)
- صُدّرت البيانات بأداة خارج هذه الحزمة. **السبب:** شبكة المكتب تقطع بروتوكول Postgres على المنفذ 5432 (`ECONNRESET`)، فاتصلت الأداة بـNeon عبر HTTPS (المنفذ 443) بمكتبة `@neondatabase/serverless`.
- الناتج `store.json` بصيغة الخادم نفسها، ومعه كلمات المرور المشفّرة. وُضع على الخادم مكان `data/store.json`.
- لا يلزم تكرار ذلك.

## 3. البنية

```
server.js          الخادم (وحدة http الأصلية): ملفات ثابتة من الذاكرة + /api/* + /healthz
index.html         الصفحة الوحيدة (فيها الشعار مضمّناً)؛ تستدعي css/style.css?v=N و js/app.js?v=N
js/app.js          الواجهة كاملة + المزامنة مع الخادم (≈190KB، كود مكثّف في دالة واحدة ذاتية التنفيذ)
css/style.css      التنسيق
assets/            logo-full.png · logo-mark.png
data/              ← يُنشأ تلقائياً على الخادم: store.json + backups/ (خارج Git)
render.yaml        إعداد Render (احتياطي)
tools/smoke.js     الفحص: npm run check
tools/copy-db.js   نسخ بين قاعدتي Postgres
```

الاعتمادية الوحيدة `pg`، وهي لا تُحمَّل إلا إذا ضُبط `DATABASE_URL`. في وضع الملف الحالي يعمل الخادم بمكتبات Node الأساسية فقط.

### نموذج البيانات
مستند واحد:
```
{ v: 7,
  users:    [{ id, login, name, role: 'member'|'manager'|'observer', admin, must, pw }],
  projects: [{ id, name, img, memberId, managerId, sections, steps, ops, stages, links, requests: [{ id, kind, title, msgs, tasks, seen, decision }] }],
  events, seen, perm, committee: { sections } }
```
- **`rev`:** رقم يزيد مع كل حفظ.
- **`pw`:** موجود على الخادم فقط. يُحذف قبل الإرسال بالدالة `strip()`، فلا يصل إلى المتصفح.
- **صور المشاريع:** نص base64 داخل المستند (JPEG بعرض 1000px أقصى، بجودة 0.8، بالدالة `readImg()`). لذلك يكبر المستند مع الصور، وحجمه اليوم ≈1.4MB.
- **مرفقات المحادثة:** الاسم والحجم فقط، لا الملف نفسه.

### الواجهة البرمجية
| الطلب | الوظيفة |
|---|---|
| `GET /api/state` | هل البيانات مهيّأة، ونوع التخزين |
| `POST /api/bootstrap` | أول تشغيل فقط، على تخزين فارغ: يرفع البيانات الأولية (حساب `eyad` / `admin1234`) |
| `POST /api/login` | `{login, password}` ← `{token, uid, must}`. الأرقام العربية تُحوَّل، والتجزئة القديمة تُرقّى تلقائياً. |
| `GET /api/data[?rev=N]` | المستند كاملاً، أو `{same:true}` إن لم يتغيّر |
| `PUT /api/data` | `{rev, data}`. برقم إصدار قديم ← 409 مع المستند الحالي. غير المسؤول لا يغيّر `users` ولا `perm`. |
| `POST /api/password` | تغيير كلمة المرور (6 أحرف على الأقل) |
| `GET /healthz` | فحص الحياة |

### المزامنة في المتصفح (`js/app.js`)
| الدالة | الوظيفة |
|---|---|
| `boot()` | يسأل `/api/state`. إن وجد التخزين فارغاً رفع البيانات الأولية. يستعيد الجلسة من localStorage، ويشغّل مؤقّت التحديث المشروط بالنشاط. |
| `pull()` | كل 15 ثانية (بشرط النشاط) أو عند التركيز على التبويب: `GET /api/data?rev=N`. لا يحدّث والمستخدم يكتب أو يسحب عنصراً أو في نافذة منبثقة (`uiBusy()`). |
| `save()` ← `schedulePush()` ← `push()` | يرسل المستند كاملاً بعد 400ms من أي تعديل. عند 409 يدمج دمجاً ثلاثياً (`merge3()`: الأساس · نسخته · نسخة الخادم) ويعيد الإرسال. عند انقطاع الشبكة يعيد المحاولة كل 5 ثوانٍ. |
| `writeCache()` | نسخة أمان في localStorage (`sankari-csr-cache`). إن عاد الخادم بإصدار أقدم منها، عرض `offerLocalRecovery()` على المسؤول استرجاعها. |
| `downloadBackup()` · `importBackup()` | نسخة احتياطية يدوية من قائمة الاسم (تنزيل أو نسخ أو استيراد، بالدمج أو الاستبدال). لا تحوي كلمات المرور. |

> الكود فيه أيضاً فرع قديم لـSupabase (`CFG` / `SB` / `rpc()`)، **لا يعمل** لأن `index.html` لا يحمّل `config.js`. تُرك كما هو.

## 4. التخزين

يختار الخادم الوضع عند التشغيل في `makeStore()`:

### 4-أ. وضع الملف (المستعمل الآن): بلا `DATABASE_URL`
- **المكان:** `DATA_DIR` إن ضُبط، وإلا `data/` بجانب `server.js`.
- **`store.json`:** المحتوى `{"rev": N, "doc": {...}}`. يُكتب كاملاً عند كل حفظ عبر ملف مؤقت `store.json.tmp` ثم إعادة تسمية، فلا يتلف الملف عند انقطاع مفاجئ.
- **`backups/store-YYYY-MM-DD.json`:** نسخة لكل يوم، تُستبدل عند كل حفظ في اليوم نفسه.
- **⚠ لا حذف تلقائي للنسخ اليومية في هذا الوضع.** يتراكم ملف بحجم المستند (≈1.4MB اليوم) لكل يوم فيه نشاط، أي ≈0.5GB في السنة. احذف القديم دورياً، أو أضف حذفاً تلقائياً بنمط فرع postgres.
- **السجل عند التشغيل:** `CSR platform on :PORT · storage: file`.

### 4-ب. وضع Postgres: مع `DATABASE_URL`
- جدول `csr_store` (الصف `main`: ‏`rev` + `doc` من نوع JSONB)، وجدول `csr_backup` (صف لكل يوم، مرة كل ساعة على الأكثر، آخر 30 يوماً).
- **السجل عند التشغيل:** `storage: postgres`.

### 4-ج. استرجاع نسخة (وضع الملف)
1. **أوقف الخدمة.** الخادم يحمّل البيانات في الذاكرة مرة واحدة عند التشغيل، ويكتبها فوق الملف مع أول حفظ.
2. انسخ `store.json` الحالي جانباً.
3. ضع النسخة المطلوبة مكان `data/store.json`، مثلاً من `backups/store-2026-10-20.json`. صيغتها نفسها، و`rev` فيها قد يكون `null` أو أقل، ولا بأس بذلك.
4. شغّل الخدمة. سيُطلب من المستخدمين تحديث الصفحة.

بديل من الواجهة: قائمة اسم المسؤول ← **استيراد نسخة احتياطية**.

## 5. التشغيل على الخادم الخاص

```
npm ci --omit=dev          # يثبّت pg فقط (لا يُستعمل في وضع الملف، لكنه مطلوب في package.json)
SESSION_SECRET=... node server.js
```
- **Node:** ‏18 أو أحدث. ‏`engines` تقول 22.x، وهذا تحذير لا يمنع التشغيل.
- **مدير عمليات:** يُبقي الخادم يعمل ويعيد تشغيله، مثل pm2 أو systemd أو Passenger في cPanel.
- **⚠ نسخة واحدة فقط من الخادم.** البيانات في ذاكرة العملية، فلا تشغّل cluster ولا أكثر من instance على الملف نفسه، وإلا كتب كل منها فوق الآخر.
- **إن كان أمامه nginx:** الضغط والـETag يصدران من الخادم نفسه، فلا حاجة لضبطهما في nginx. اجعل `client_max_body_size` ‏25m على الأقل، لأن المستند يُرسَل كاملاً مع الصور (`MAX_BODY` في `server.js`).
- **المنصة تعمل من جذر النطاق.** تحت مجلد فرعي مثل `example.com/csr/` تحتاج تعديلاً في `server.js`، لأن المسارات تُقرأ من الجذر.
- **انسخ المجلد `data/` احتياطياً بانتظام.** هو المكان الوحيد للبيانات الآن.

## 7. قواعد العمل على الكود

1. **عند تعديل `js/app.js` أو `css/style.css`** ارفع `?v=N` في `index.html` (الآن 12). المتصفحات تخزّن هذين الملفين سنة كاملة.
2. **`npm run check` قبل كل تسليم.** يشغّل الخادم بتخزين ملف مؤقت، ويفحص 32 بنداً:
   - صياغة الملفات الثلاثة، والضغط، و304، وقواعد التخزين في المتصفح.
   - منع قراءة ملفات الخادم من المتصفح.
   - التهيئة، والدخول بالأرقام العربية، والرمز المزوَّر.
   - كلمات المرور لا تخرج، و409 عند التعارض، وغير المسؤول لا يرفع صلاحياته.
   - تغيير كلمة المرور.

   أضف فحصاً لكل ميزة خادم جديدة.
3. **لا تُرجِع التحديث الدائم.** أي مؤقّت أو طلب دوري جديد في الواجهة يجب أن يحترم شرط «الصفحة ظاهرة ونشطة» (`IDLE_MS` و`document.hidden` في `boot()`).
4. **كل حفظ يرسل المستند كاملاً.** لا تضع فيه بيانات كبيرة، مثل ملفات مرفقة أو صور بدقة عالية. هذا يحتاج تخزيناً منفصلاً للملفات.
5. **الكود في `js/app.js` مكثّف** (أسطر طويلة وأسماء قصيرة). حافظ على أسلوبه عند الإضافة، وابحث بأسماء الدوالّ المذكورة في القسم 3.
6. **الملفات بترميز UTF-8 ونهايات أسطر LF.** انتبه عند التعديل على ويندوز.

## 8. بديل: النشر على Render (غير مستعمل الآن)

`render.yaml` جاهز: **New +** ← **Blueprint** ← المستودع ← يُطلب `DATABASE_URL`. ‏`SESSION_SECRET` يتولّد تلقائياً.

**قرص Render المجاني مؤقت.** لذلك يلزم هناك وضع Postgres، أي `DATABASE_URL`، وإلا ضاعت البيانات عند كل نوم.

حدود الخطة المجانية:
- **Render:** ‏750 ساعة شهرياً لكل مساحة عمل، وينام الخادم بعد 15 دقيقة بلا طلبات.
- **Neon:** ‏100 ساعة حوسبة، و1GB تخزين، و5GB نقل بيانات شهرياً.

تعديلات 1.1.0 هي ما يجعل المنصة ضمن هذه الحدود.
